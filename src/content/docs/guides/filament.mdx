`albertoarena/filament-truss` adds a **Database schema** page to a Filament panel: the same live ER diagram Truss draws, rendered as a page of the panel rather than as a frame around something else.

<ThemedImage

/>

**Structure only, never row data.** Tables, columns, indexes, foreign keys and column defaults, which is Truss's promise unchanged. Living inside an admin panel does not relax it, and the plugin has no write path of any kind.

## What it is not

It is not the Truss dashboard in an iframe, and it is not a second renderer. The page calls `Truss::payload()`, the facade method, and hands the array to Truss's own frontend embedded in the page. There is no schema endpoint of its own and no reimplementation of the diagram: the pipeline is Truss's, re-driven in a different place.

The diagram reads the panel's own CSS custom properties, so a panel with a custom colour or radius needs no configuration, and light and dark follow the panel with no reload.
